# Commerce, localization and mobile increment — implementation plan

**Decision:** Continue in the existing sandbox repository, with no subagents and no desktop mount access. This increment does not represent completion of the 51-page master scope or a live-payment launch. The user has requested their own infrastructure; actual deployment remains blocked until host/DNS details arrive.

1. **Reference map.** Assess all nine PDFs, distinguish documented facts from program objectives, and preserve conflicting donation-total definitions. Do not ship legal originals or publish sensitive identifiers.
2. **Commerce slice (tests first).** Add a versioned PostgreSQL migration for organization-scoped catalog items, localized editorial translations and inquiry records. Write failing tests for catalog validation, publication without reviewed languages, tenant scoping and public-only approved reads; implement Nest service and protected management endpoints. Restrict payment status to none: requests are inquiries, never orders or receipts. Keep public inquiry submission feature-flagged off until a reviewed privacy policy is configured. Add management UI and public catalog pages with useful empty/error states.
3. **Localization (tests first).** Add `/gu`, `/hi`, `/en` public routes; a registry/dictionary for navigation, home, shop and contact text; valid document `lang`, per-locale metadata and a language switch. Default `/` goes to `/gu`. Fallback must be explicitly labeled; unreviewed catalog translations stay private. Preserve `/staff`, initially English except catalog editor until comprehensive staff localization is funded and reviewed.
4. **Favicon/PWA.** Generate all standard icon sizes from the supplied 300×314 logo without altering its original. Add web manifest, registration and minimal service worker. Cache only installation assets and an explicitly public offline screen, never authenticated routes, API, cart or queries. No background sync/push promised.
5. **Verification.** Run API/web unit tests, TypeScript checks, Python/Go tests, SQL migration and restricted-role access checks, Compose/Caddy config, a browser smoke test at desktop/mobile width and build-time noindex checks. Commit and archive only verified source. Update OpenAPI and self-hosting docs with exact migration and setup steps.

**Outstanding for a live shop:** SKU/inventory/price/tax/shipping data approved by owner; policies; Razorpay merchant/test/live setup and signed webhooks; reconciliation; legal/tax review; reviewed Gujarati/Hindi copy; self-hosted server/DNS. Do not turn an inquiry into a payment or claim the final platform is operational before these gates.
